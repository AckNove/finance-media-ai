# Phase 2 · 决策登记（decision register）

本文件只记录**做了选择、且有代价**的决定。每条写四件事：选了什么、为什么、放弃的代价、什么情况下
应该翻案。没有代价的决定不写。

## D1 视频引擎用 OpenKatana 0.1.3，不自己写渲染器

- **选择**：`tools/openkatana`（Apache-2.0，固定 commit `f3b09107a9828ef770f5bf63116cd418197c15c2`，
  75 个工具），通过 `backend/app/capabilities/media/openkatana.py` 适配。
- **理由**：它已经解决了组合文档 → Chromium 逐帧 → ffmpeg 编码这条链路，且有 36 个 AE 风格效果配方
  与 timeline 语义。自己写等于重做浏览器渲染与合成。
- **代价**：受它 0.1.x 的契约约束（`easing` 只有三种、`loop` 只能放镜头层、转场 dir 词表分裂），
  每次踩到都要读源码确认而不是猜；渲染慢（40 秒片约 19 分钟）。
- **翻案条件**：若需要 4K/60fps 批量或需要 GPU 合成，评估其它引擎。

## D2 适配层强制把 `tools/ffmpeg/bin` 前置到子进程 PATH

- **选择**：`OpenKatanaEngine.environment()` 里改 `PATH`，并删掉 `PYTHONPATH`；`health()` 校验引擎
  自述的 ffmpeg 必须**等于**项目内的那一个。
- **理由**：引擎全项目用裸 `'ffmpeg'`（`agent_api.py:60`、`cli.py:181`），PATH 上是 4.2.2 → 视频导入
  必然失败且报 `Unrecognized option 'fps_mode'`，很难想到是版本问题。
- **代价**：子进程环境被我们改写，行为与「用户直接敲 `python -m openkatana`」不同；排查时必须记得这点。
- **翻案条件**：引擎支持显式 `--ffmpeg` 参数时，改用它而不是改 PATH。

## D3 分镜用 CSV 作为数据文件，不写成脚本常量

- **选择**：`storyboard/storyboard.csv`，16 个必需列，`backend/app/media/storyboard.py` 硬校验。
- **理由**：任务书要求「脚本不得直接进 FFmpeg，必须先转分镜」。数据文件才能被校验、被拒绝、
  被另一个程序读；脚本常量做不到「写错就报错」。
- **代价**：多一层 schema 维护；列名拼错会直接失败（这是**故意**的，不静默忽略）。
- **翻案条件**：镜头数上百、需要复用片段时，再考虑换成带继承的结构化格式。

## D4 素材授权不明一律拒绝渲染（不是「记录一下继续用」）

- **选择**：`assert_renderable()` 在渲染前硬拦；`commercial_use != "allowed"` 抛 `rights_unclear`。
- **理由**：授权风险是**事后无法修复**的负债——片子发出去了，撤不回来。
- **代价**：可用素材变少。本轮因此只拿到 1 个真实视频来源（用两个入点），指标「≥2 个真实视频片段」
  只部分满足。
- **翻案条件**：拿到明确书面授权的新来源时补上；不得用生成视频冒充。

## D5 所有音频输入统一转 AAC `.m4a`

- **选择**：`audio/` 目录全部是 `.m4a`（score_bed、orbit_loop、6 个音效）。
- **理由**：V2.1 实测 MP4 容器装不了 PCM（`Could not find tag for codec pcm_s16le in stream #1`）。
  这是容器约束，不是偏好。
- **代价**：多一步转码（192k AAC），有轻微有损。
- **翻案条件**：若将来输出 MOV/ProRes 母版，可改回无损 PCM。

## D6 时间轴用 `fit:"cover"` + `cover:true` 处理 16:9 → 9:16

- **选择**：非 `solid` 镜头一律显式写这两个字段（在 `timeline.py` 的 `camera_block()` 里统一加）。
- **理由**：NASA 素材是 16:9，画布是 9:16。不裁切就会出现上下黑边，且推镜时黑边会移动，非常丑。
- **代价**：裁掉画面两侧约 68% 的横向内容；主体必须居中才安全。
- **翻案条件**：若素材本身就是竖屏，可以改 `fit:"contain"` 或按镜头单独指定。

## D7 不做真人配音，也不假装有

- **选择**：全片只有字幕（7 条）+ 配乐 + 音效；报告、结尾卡、视觉说明三处明确写「无真人配音」。
- **理由**：任务书禁止付费 TTS 与来源不明的语音；本机只有 SAPI（V2.1 已判定它不能作为正式配音标准）。
- **代价**：片子说服力弱于有人声的版本。
- **翻案条件**：Phase 3+ 授权本地开源 TTS 或真人录音。

## D8 写 8 份文档而不是 1 份总报告

- **选择**：按任务书 §五 的固定文件名产出八份（适配层 / 导入 / 分镜 / 时间轴 / 溯源 / 演示片 /
  质检 / 决策）。
- **理由**：这八件事的读者不同（工程师看适配层与时间轴，法务与编辑看溯源，审核者看质检与演示片）。
  合成一份会导致九成读者要翻过八成内容。
- **代价**：有重复叙述（每个文件都重述了关键数字）。
- **翻案条件**：文档数量本身不是目标，下一阶段可按读者合并。

## D9 渲染前做静态契约体检，而不是「渲染失败再改」

- **选择**：`raw/_work/check_compositions.py` 在渲染前检查组合文档的 style 键、track 属性、easing、
  关键帧范围、顶层键、字体字段名。
- **理由**：一次组合渲染要几分钟，改一个字重跑一次，成本远高于静态检查（毫秒级）。
- **代价**：这份体检器要知道引擎的白名单，引擎升级时要同步维护。
- **翻案条件**：若引擎自带 dry-run 校验工具，直接用它。

## D10 引擎调用全部记 JSONL，不散落在 print 里

- **选择**：`engine_calls.jsonl`，每次调用一行（`tool/ok/duration_ms/attempt/error`）。
- **理由**：Phase 2 共 **277 次调用**，其中 215 次是渲染轮询。没有日志就没法回答「到底哪里慢、
  失败了几次、是不是同一个错反复重试」。
- **代价**：日志文件会随流程增长（本任务约几百行，可接受）。
- **翻案条件**：接入正式日志系统后改为结构化日志。
