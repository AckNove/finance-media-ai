# Phase 2 收尾整改决策登记

> 记录本轮（V2.2 Phase 2 Closure Remediation）做出的、会影响最终交付形态的决定。
> 每条都写：决定是什么、为什么、影响谁、残留风险。

## D-01 room tone 删除，不补假文件

- **决定**：`storyboard.csv` 里 `sh01` 的 `sound_effect` 由 `room tone` 改为 `none`。
- **为什么**：该音效从来没有生成过文件、没有导入项目、没有进入时间轴，是只存在于文本里的
  空承诺；任务书明确「不允许为了让数字自洽而伪造素材」。
- **影响**：音效事件数 7 → 6，与实生成文件数、时间轴音效轨数三者相等。
- **残留风险**：无。若将来要房间底噪，必须走「生成 → 登记 → 导入 → 进时间轴 → 一致性检查」全流程。

## D-02 narration 与 subtitle 用显式开关解耦

- **决定**：`subtitle_events(source="subtitle"|"narration"|"none")`，默认只读 `subtitle`；
  `build_document()` 在调用点显式写 `source="subtitle"`。
- **为什么**：把「旁白不会自动变字幕」从隐含行为变成代码契约，避免未来一行改动造成双字幕。
- **影响**：`sh07` 的重复字幕删除（卡面已有同一句大字）。
- **残留风险**：`source="narration"` 若被误用，会把带语气词的口播稿直接印上屏——但这是
  显式选择，且测试覆盖了三种取值的语义。

## D-03 结尾卡署名逐条列出，且只能来自登记表

- **决定**：结尾卡从 `source_register.csv` 读取 `credit` 列，逐条渲染；`credit` 为空即
  构建失败，禁止写概括语（如「NASA 公共领域影像」）。
- **为什么**：三个素材分属三个不同作者/项目，压成一句等于没有署名；且代码强制可避免
  「文档写了、画面没写」。
- **影响**：结尾卡从 3 行变为 6 行署名 + 免责说明 + 统计行 + 结束语；`sh07` 时长
  5.5 s → 8.0 s。
- **残留风险**：登记表若被写入错误 credit，画面会忠实地显示错误内容——所以登记表的
  `verification_status` 与 sha256 校验是这条链的护栏。

## D-04 不联网复核 NASA 页面，把三项标为「待核实」

- **决定**：本轮只做离线核验（登记表 / 上游 `sources.json` / sha256 / ffprobe），
  NASA SVS 逐页条款、NOAA-JPSS 数据条款、画面内第三方内容三项标为待核实。
- **为什么**：本轮授权范围是收尾整改，联网逐条抓取不在授权内；而「不确定就写不确定」
  比编一个「已核实」更负责。
- **影响**：`phase2_credit_verification_report.md` 第 4 节；报告不给「可无条件商用」结论。
- **残留风险**：**对外发布前必须人工复核这三项**。这是本轮最重要的未关闭风险。

## D-05 同一 NASA 视频的两个入点不伪装成两个来源

- **决定**：保留 `S03A`（0–6 s）与 `S03B`（12–17 s），但全部文档写明二者是同一文件的两个
  入点；「≥2 个真实视频片段」记为**部分完成**。
- **为什么**：任务书明确禁止把同一文件的两个入点描述成两个独立来源；也不要求本轮强行补来源。
- **影响**：所有计数类报告（QC、演示报告、署名报告）都带这条说明。
- **残留风险**：真实素材多样性仍然不足，正式内容生产前需要第二个经授权的视频来源。

## D-06 音频四个口径分开统计，并做成构建门禁

- **决定**：音效事件数 / 独立音效文件数 / 配乐数 / 时间轴总音轨数 四个数字分开报告；
  `audio_consistency()` 在 `--stage timeline` 里强制检查，`ok=False` 直接失败。
- **为什么**：修复前同一个「音效数」在四个地方是三个数字（7 / 6 / 10 vs 15 行），
  根因是硬编码列表 + 名字对不上 + 一个不存在的值。
- **影响**：`sfx_schedule()` 改为从分镜派生；QC 新增 `audio_counts_consistent` 检查项。
- **残留风险**：无。任何新增音效都必须先写进分镜，否则构建直接报错。

## D-07 全片时长 40.0 s → 42.5 s

- **决定**：结尾卡帧数 165 → 240（8.0 s），全片 40.0 s → 42.5 s。
- **为什么**：逐条署名（6 行）需要更多停留时间才能读完；原 5.5 s 会在两行折行的长署名上
  显得仓促。
- **影响**：时间轴 1200 → 1275 帧；仍在任务书要求的 30–45 s 区间内。
- **残留风险**：重渲染耗时增加（约 +3%）。

## D-08 不擅自做响度标准化

- **决定**：保持当前混音（集成响度约 −23.6 LUFS），只给出客观说明与可选方案，不自动
  加 `loudnorm` 或提高配乐音量。
- **为什么**：任务书写明「不得未经批准擅自改变音频标准」。
- **影响**：成片比流媒体平台常见的 −14 LUFS 目标低约 9 LU，播放时可能需要调高音量。
- **残留风险**：若对外发布，建议按目标平台做一次响度归一——需要用户批准后另开一轮。

## D-09 自动检查只判技术指标，不判好不好看

- **决定**：`--stage qc` 与 `--stage review` 只输出可测量的事实（分辨率、音画等长、黑帧、
  静音、削波、响度、音效与配乐的分窗音量差、关键帧），并在报告里明写「不等于视觉质量通过」。
- **为什么**：程序判断不了观众喜不喜欢；把自动 QC 当验收结论是本轮任务书点名禁止的事。
- **影响**：`phase2_visual_review_report.md` 只提供复核材料与索引，结论留给人工。
- **残留风险**：无（这是纪律，不是缺陷）。

## D-10 本轮不 commit、不 push

- **决定**：本轮产生的所有改动只留在工作区。
- **为什么**：本轮任务书第 13 条明令「不执行 git commit 或 git push」；
  `AGENTS.md` 里写的「每轮改动即推送」与历史任务书的冲突处理规则是「**以当轮为准**」。
- **影响**：仓库仍停在 `181b1b1`，工作区有未提交改动；需用户在下一轮明确授权后再同步。
- **残留风险**：若后续轮次遗忘，改动可能长期不入库——最终报告 L 节已列明待提交文件。

## D-11 没有配音，且不伪装

- **决定**：不调用任何 TTS/云服务，不使用系统 SAPI 冒充正式配音，不把字幕当配音。
- **为什么**：本轮无付费授权、无真人录音；任务书禁止伪造音轨。
- **影响**：成片只有配乐与音效两层；`narration` 文本完整保留在分镜里供将来配音使用。
- **残留风险**：成片目前是「无声解说」版本，正式内容生产前必须补真人配音或经批准的 TTS。
